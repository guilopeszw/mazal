# E Agent, Deco e Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar o MCP determinístico da Mazal, conectá-lo a um Agent na Deco, integrar a narração segura ao frontend e preparar um caminho de demo reproduzível antes do freeze.

**Architecture:** `apps/mcp` será um servidor MCP stateless em Streamable HTTP, protegido por bearer token e implantado na Vercel. A Deco terá dois objetos separados — uma Custom Connection para o MCP e um Agent Mazal que usa seus quatro tools — enquanto `/api/chat` conversa com esse Agent, valida uma narração estruturada e aplica fallback para fixtures ou templates seguros.

**Tech Stack:** TypeScript, Hono, `@modelcontextprotocol/server`, `@modelcontextprotocol/hono`, Zod, Vitest, Vercel e deco Studio.

## Global Constraints

- Todo número exibido vem de TypeScript determinístico; o LLM nunca calcula, estima ou arredonda.
- O MCP expõe exatamente quatro tools: `diagnose_campaign`, `predict_campaign`, `build_recovery_plan` e `execute_plan`.
- `packages/*` e o contrato congelado não são alterados por E.
- `apps/web` só pode ser alterado dentro de `POST /api/chat` e seus arquivos diretamente co-localizados.
- `execute_plan` é simulado, sem cliente de escrita Meta, e rejeita ações com `actor: 'seller'`.
- A narração desta versão é somente pt-BR, curta e na ordem veredito → evidência → plano.
- Cada mensagem faz no máximo uma execução do Agent/LLM e nunca ultrapassa o limite de duas chamadas de modelo por interação.
- A integração Meta é read-only, desativada por padrão e nunca bloqueia CSV ou fixtures.
- A branch de trabalho é `joaquim/feat/agent-mcp`; o destino da integração depende de decisão do time porque `stage` não existe.

## Resumo executivo

As dependências determinísticas estão verdes: 85 testes, typecheck e backtest reproduzível. Nenhuma entrega de E existe ainda; `apps/mcp`, `/api/chat`, prompts, respostas capturadas e deck final não foram iniciados. O risco crítico é que as duas fixtures atuais terminam com diagnóstico saudável e plano vazio, por isso A/B precisam substituí-las por casos que satisfaçam o contrato da demo. O caminho recomendado começa pelo MCP e seus quatro tools, segue por deploy e conexão Deco, depois narração segura e integração com o frontend de D. A demo usa respostas capturadas e fallback determinístico, mantendo o modo live apenas para preparação e para a superfície da Deco. A integração Meta fica isolada como stretch read-only; writes reais entram somente como evolução futura. Ferramenta de autoria do deck fica deliberadamente adiada, sem bloquear conteúdo e roteiro.

### `POST /api/chat` em `apps/web`

- Create after D lands: `apps/web/app/api/chat/route.ts` — contrato HTTP, cálculo/carregamento de contexto e resposta completa sem streaming.
- Create: `apps/web/app/api/chat/schema.ts` — request/response, `conversationId`, `source` e warnings.
- Create: `apps/web/app/api/chat/deco-provider.ts` — thread, execução e leitura do Agent da Deco.
- Create: `apps/web/app/api/chat/narration.ts` — templates com referências de campos e interpolação determinística.
- Create: `apps/web/app/api/chat/validation.ts` — rejeita números literais e caminhos não permitidos.
- Create: `apps/web/app/api/chat/cache.ts` — hash de cenário, mensagem, contexto e versão do prompt.
- Create: `apps/web/app/api/chat/fixtures/*.json` — respostas aprovadas para os dois casos.
- Create: `apps/web/app/api/chat/*.test.ts` — live, fixture, template, warnings e continuidade por `conversationId`.

O request aceita `scenarioKey` ou inputs brutos validados, além de `userMessage` e `conversationId` opcional. A evolução de produção troca esses inputs por `analysisId`, resolvido por um `AnalysisContextProvider` sobre snapshots persistidos; banco e filas não entram neste build.

## Dependências e bloqueios

```text
A define critérios ─┐
                    ├─ B regenera fixtures ── narração ── captura ── demo/deck
MCP ── deploy ── Deco Connection ── Deco Agent ────────────────┘
                                      │
D entrega apps/web ───────────────────┴─ /api/chat ── sidebar

Caminho principal verde ── adapter Meta read-only ── leitura ao vivo opcional
```

- A/B são dependência externa, mas o planejamento assume que entregarão os outputs acordados.
- D é esperado a tempo; se não entregar, a Deco é a superfície oficial de fallback e E não assume o frontend.
- A contingência de assumir `packages/data` já foi encerrada: B entregou benchmarks e os testes estão verdes.
- A máquina local possui Node 22, embora o projeto exija Node 24. Deploy e validação final precisam usar Node 24.
- O schema real do tool oficial Meta só será fechado depois de uma conexão read-only bem-sucedida; até lá, o adapter permanece desativado.

## Riscos e pontos de atenção

| Risco | Consequência | Mitigação |
|---|---|---|
| Fixtures continuam saudáveis | Demo não mostra vazamento nem plano | Gate P0 de A/B; não mascarar com mock narrativo |
| Modelo escreve números | Viola a principal garantia do produto | LLM retorna templates com referências; TypeScript interpola valores |
| Deco/modelo/rede falha | Chat vazio ou imprevisível | Fixture para cenários conhecidos; template para desconhecidos; warning visível |
| Log em memória reinicia | Recibos não formam histórico durável | Declarar simulação; interface permite storage futuro |
| D atrasa | `/api/chat` não pode ser integrado | Demo diretamente no Agent da Deco |
| Runtime Node incorreto | Falha apenas no deploy | Fixar Node 24 e executar smoke test remoto |
| Roteiro mantém números antigos | Contradição com backtest/engine | Auditoria automática/manual antes da captura |
| Meta OAuth consome o prazo | Atrasa o caminho principal | Feature flag off; executar somente com buffer real |
| Tools Meta de escrita são anexados | Bypass de aprovação e risco real | Conexão read-only; writes futuros por executor controlado |
| `stage` ausente | PR sem destino compatível com AGENTS | Não recriar sozinho; decisão explícita antes da integração |

## Critérios de aceite

### MCP

- `tools/list` retorna exatamente os quatro nomes aprovados.
- Cada tool valida input em runtime e devolve JSON compatível com os tipos públicos.
- Benchmark é injetado no servidor; clientes nunca enviam a tabela inteira.
- Requisição sem bearer recebe 401; token correto completa o handshake.
- Nenhum arquivo de `packages/*` é alterado.

### `execute_plan`

- Ações `mazal` são anexadas ao log e retornadas em `logged`.
- O mesmo conjunto canônico de ações produz o mesmo recibo.
- Ações `seller` são rejeitadas e nunca registradas como executadas.
- Não existe dependência, token ou cliente de escrita Meta.

### Deco

- A Custom Connection descobre os quatro tools do deploy.
- O Agent chama pelo menos um tool e a chamada aparece no Monitor.
- Uma pergunta completa retorna narração pt-BR no registro correto.
- A API key usada pelo web não aparece no navegador ou no repositório.

### Narração e chat

- Nenhum número literal produzido pelo modelo chega ao usuário.
- Toda referência é validada e interpolada a partir do contexto determinístico.
- Resposta inválida aciona fallback e warning visível.
- Cenários conhecidos funcionam sem rede no modo `fixture`.
- Cenários novos recebem template seguro no fallback.
- `conversationId` preserva o contexto entre mensagens.
- Cada interação inicia no máximo uma execução do Agent/LLM; retries usam cache ou fallback, não uma nova improvisação.
- A resposta HTTP é completa e não transmite conteúdo parcial não validado.

### Demo e pitch

- As duas fixtures produzem diagnóstico, veredito e plano coerentes com a narrativa.
- Cada frase numérica aponta para um campo real ou para `docs/slide-6.md` quando for backtest.
- Os valores de economia removidos não aparecem em tela, roteiro ou deck.
- O caminho completo é executado uma vez antes do freeze.
- Há resposta capturada, vídeo de backup e três ensaios cronometrados.

### Meta read-only

- Feature flag desligada mantém CSV/fixtures funcionando sem qualquer chamada Meta.
- Somente tools read-only são anexados.
- Campos ausentes geram erro e fallback, nunca zeros artificiais.
- O adapter não cria um quinto tool e não altera o contrato congelado.
